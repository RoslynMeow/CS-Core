\subsection{指令系统：软件与硬件的接口}

计算机系统可以粗略地划分为\textbf{软件层}与\textbf{硬件层}：软件层用高级语言、汇编语言描述算法，硬件层由晶体管、门电路与数据通路完成实际运算。二者必须约定一套共同语言，才能保证同一段程序在任意合规的实现上得到相同结果。这套共同语言就是\textbf{指令系统}，其完整的规范描述称为\textbf{指令集架构}（Instruction Set Architecture, ISA）。

\begin{definition}[指令集架构]
指令集架构是程序员可见的机器抽象：它规定了机器能够执行的全部指令、可以访问的寄存器与存储空间、支持的数据类型，以及指令的编码与寻址规则；但它\emph{不}规定这些功能如何用硬件实现。ISA 是软件与硬件之间的一份\textbf{契约}。
\end{definition}

\subsubsection{ISA 在分层体系中的位置}

同一个 ISA 可以有多种不同的硬件实现（例如 MIPS 的单周期、多周期、流水线实现，或 x86 的历代处理器）。只要它们对同一程序产生相同的结果，就都“实现了”该 ISA。把“做什么”（ISA）与“怎么做”（微架构）分离，带来的好处是：编译器只需面向 ISA 生成代码，硬件工程师只需按 ISA 设计电路，软硬件得以\textbf{独立演进}。

\subsubsection{ISA 规定的内容}

一套完备的 ISA 通常需要定义以下要素：

\begin{itemize}
    \item \textbf{指令格式}：操作码与操作数如何编码，指令有多长；
    \item \textbf{寄存器组}：有哪些寄存器、数量、位宽与用途约定；
    \item \textbf{寻址方式}：如何由指令字段定位到操作数或内存地址；
    \item \textbf{数据类型}：支持哪些整数宽度、是否有浮点、字节序；
    \item \textbf{中断与异常}：发生异常时寄存器与栈如何维护；
    \item \textbf{I/O 模型}：使用内存映射 I/O 还是独立 I/O 端口。
\end{itemize}

本章以经典的 RISC 架构 \textbf{MIPS} 为主线讲解，并在末尾对比 CISC 与 RISC 的设计哲学。

\subsection{指令格式}

\subsubsection{指令的组成}

一条机器指令本质上是一串定长或变长的二进制位，通常由两部分组成：

\begin{itemize}
    \item \textbf{操作码}（opcode）：指明这条指令“做什么”；
    \item \textbf{操作数域}：指明“对谁做”，可以存放寄存器号、立即数、或地址偏移。
\end{itemize}

MIPS 采用\textbf{定长 32 位}指令，按用途分为三种格式：R 型（寄存器型）、I 型（立即数型）、J 型（跳转型）。

\subsubsection{各种寻址方式的有效地址计算式}

\begin{itemize}
    \item \textbf{立即数寻址}：操作数就在指令中，不存在访存，操作数 $= \text{imm}$；
    \item \textbf{寄存器寻址}：操作数 $= R[i]$，速度最快；
    \item \textbf{直接寻址}：$EA = A$，指令直接给出内存地址；
    \item \textbf{间接寻址}：$EA = M[A]$，内存中的内容再作为地址，可一次访存两次取值；
    \item \textbf{寄存器间接寻址}：$EA = R[i]$，寄存器里存的是地址；
    \item \textbf{基址寻址}：$EA = R_{\text{base}} + d$，适合定位数组/结构体基址；
    \item \textbf{变址寻址}：$EA = R_{\text{index}} + d$，适合循环遍历数组；
    \item \textbf{相对寻址}：$EA = PC_{\text{next}} + (d \ll 2)$，用于分支，代码可重定位；
    \item \textbf{堆栈寻址}：$EA = SP$，按下推（push，$SP \gets SP - 4$）与弹出（pop，$SP \gets SP + 4$）存取。
\end{itemize}

\subsubsection{完整例题：把汇编翻译成机器码}

\begin{example}[汇编 $\to$ 机器码]
把 \texttt{add \$t0, \$t1, \$t2} 翻译为 32 位机器码。已知 R 型指令：\texttt{add} 的 op $=0$、funct $=0x20$；寄存器号 \$t0=8，\$t1=9，\$t2=10。

\begin{enumerate}
    \item 确定格式：\texttt{add} 是 R 型，目标寄存器写入 rd，源在 rs 与 rt。因此 rd $=\$t0=8$，rs $=\$t1=9$，rt $=\$t2=10$。
    \item 逐字段转二进制：
    \[
    \underbrace{000000}_{op}\ \underbrace{01001}_{rs=9}\ \underbrace{01010}_{rt=10}\ \underbrace{01000}_{rd=8}\ \underbrace{00000}_{shamt}\ \underbrace{100000}_{funct=0x20}
    \]
    \item 拼接为 32 位并按每 4 位一组转十六进制：
    \[
    0000\ 0001\ 0010\ 1010\ 0100\ 0000\ 0010\ 0000 = \texttt{0x012A4020}
    \]
\end{enumerate}
故机器码为 \texttt{0x012A4020}，与表~\ref{tab:mips_machine} 一致。
\end{example}

\begin{example}[机器码 $\to$ 汇编：反向译码]
给定机器码 \texttt{0x012A4020}，还原其汇编指令。
\begin{enumerate}
    \item 展开为二进制：\texttt{0000 0001 0010 1010 0100 0000 0010 0000}。
    \item 按 R 型切分字段：op $=000000$（即 R 型），rs $=01001=9$，rt $=01010=10$，rd $=01000=8$，shamt $=00000$，funct $=100000=0x20$。
    \item 查功能码表：op $=0$ 且 funct $=0x20$ 表示 \texttt{add}。
    \item 组装：rd $=8$（\$t0），rs $=9$（\$t1），rt $=10$（\$t2）。
\end{enumerate}
结果为 \texttt{add \$t0, \$t1, \$t2}。整个译码过程可归结为“取指 $\to$ 定格式 $\to$ 切字段 $\to$ 查表 $\to$ 组装”五步。
\end{example}

按照指令系统的复杂度，处理器可分为两大流派：\textbf{CISC}（复杂指令集计算机）与 \textbf{RISC}（精简指令集计算机）。

\begin{table}[H]
\centering

RISC 的核心理念是：\textbf{指令简单规整 $\to$ 便于流水线 $\to$ 提高主频与吞吐}。由于访存只有 Load/Store 两条指令，运算指令的延迟可控，流水线设计大为简化。这也是现代 RISC（ARM、RISC-V）在移动与嵌入式领域占据主导的原因；而 x86 通过把复杂指令在内部译码为类 RISC 的微操作，兼顾了兼容性与性能。

\subsection{过程调用与栈帧}

\subsubsection{调用约定}

过程（函数）调用需要解决四个问题：\textbf{如何传递参数}、\textbf{如何保存返回地址}、\textbf{如何保存调用者/被调用者的寄存器}、\textbf{如何返回结果}。MIPS 用一组寄存器约定来规范这些行为，见表~\ref{tab:mips_regs}。

\begin{table}[H]
\centering
\caption{MIPS 寄存器用途约定}
\label{tab:mips_regs}
\begin{tabulary}{\textwidth}{CCC}
\toprule
\textbf{寄存器号} & \textbf{名称} & \textbf{用途} \\
\midrule
\$0 & \$zero & 恒为 0 \\
\$1 & \$at & 汇编器保留 \\
\$2--\$3 & \$v0 \$v1 & 函数返回值 \\
\$4--\$7 & \$a0--\$a3 & 前 4 个函数参数 \\
\$8--\$15 & \$t0--\$t7 & 临时变量（caller-saved） \\
\$16--\$23 & \$s0--\$s7 & 保存变量（callee-saved，需恢复） \\
\$29 & \$sp & 栈指针 \\
\$30 & \$fp & 帧指针 \\
\$31 & \$ra & 返回地址 \\
\bottomrule
\end{tabulary}
\end{table}

约定要点：
\begin{itemize}
    \item \textbf{参数传递}：前 4 个参数放 \$a0--\$a3，超出部分通过栈传递；
    \item \textbf{返回值}：放在 \$v0（必要时 \$v1）；
    \item \textbf{返回地址}：\texttt{jal} 把下一条指令地址存入 \$ra，返回时用 \texttt{jr \$ra}；
    \item \textbf{寄存器保护}：\$t 系列由调用者负责保存（若需要），\$s 系列由被调用者保存并恢复。
\end{itemize}

一个遵循约定的过程体可用如下汇编模板描述：

\begin{lstlisting}[caption={MIPS 过程调用模板：保存/恢复现场}]
    # ---- 建立栈帧 ----
    addi $sp, $sp, -12    # 分配 12 字节栈帧
    sw   $ra, 8($sp)      # 保存返回地址
    sw   $s0, 4($sp)      # 保存 callee-saved 寄存器
    sw   $s1, 0($sp)
    # ---- 过程体 ----
    # ... 使用 $s0/$s1 与局部变量 ...
    move $v0, $s0         # 设置返回值
    # ---- 恢复现场 ----
    lw   $s1, 0($sp)
    lw   $s0, 4($sp)
    lw   $ra, 8($sp)
    addi $sp, $sp, 12     # 释放栈帧
    jr   $ra              # 返回调用者
\end{lstlisting}

\subsubsection{示例：数组求和}

\begin{example}[数组求和的汇编实现]
\begin{lstlisting}[caption={计算 a[0] + a[1] + ... + a[9]}]
    li   $t0, 0          # sum = 0
    li   $t1, 0          # i = 0
    la   $t2, array      # $t2 = &a[0]
loop:
    lw   $t3, 0($t2)     # $t3 = a[i]      (基址偏移寻址)
    addu $t0, $t0, $t3   # sum += $t3
    addi $t1, $t1, 1     # i++
    addi $t2, $t2, 4     # $t2 += 4 (下一个字)
    blt  $t1, 10, loop   # if i < 10 goto loop
done:
    move $v0, $t0        # 返回 sum
\end{lstlisting}
其中 \texttt{lw} 使用了基址偏移寻址（$EA = \$t2 + 0$），\texttt{blt} 由 \texttt{slt}+\texttt{bne} 组合实现，体现了 RISC“用简单指令组合出复杂语义”的思想。
\end{example}

\subsection{本章小结}

\begin{itemize}
    \item \textbf{ISA 是软硬件接口}：它规定了指令格式、寄存器、寻址方式与数据类型，是可移植性的基础；同一 ISA 可有多种微架构实现。
    \item \textbf{MIPS 三种格式}：R 型（6/5/5/5/5/6）、I 型（6/5/5/16）、J 型（6/26），op 固定占最高 6 位，便于快速译码。
    \item \textbf{寻址方式}统一用有效地址 $EA$ 刻画：立即/寄存器无需访存，直接/间接/寄存器间接/基址/变址/相对/堆栈各有公式与适用场景。
    \item \textbf{指令分类}：算术、逻辑、访存、分支、跳转；只有 Load/Store 访存是 RISC 的关键特征。
    \item \textbf{汇编与机器码}可双向翻译：定格式 $\to$ 切字段 $\to$ 转进制（或查表）。
    \item \textbf{过程调用}依赖调用约定：\$a 传参、\$v 返回、\$ra 存返回地址、\$t/\$s 划分保存责任，\$sp 维护向低地址生长的栈帧。
\end{itemize}

\subsection{常见误区}

\begin{itemize}
    \item \textbf{把 ISA 与微架构混为一谈}：ISA 是软件可见的抽象，微架构是具体电路实现；同一 ISA 的性能可以差别巨大。
    \item \textbf{认为所有 MIPS 指令都能访存}：只有 \texttt{lw}/\texttt{sw} 等 Load/Store 指令访问内存，算术逻辑指令只操作寄存器。
    \item \textbf{混淆直接寻址与间接寻址}：直接寻址 $EA = A$ 只访存一次；间接寻址 $EA = M[A]$ 需访存两次。
    \item \textbf{混淆基址与变址}：两者公式都是 $R+d$，区别在语义——基址寄存器放“基址”、偏移变，变址寄存器放“下标”、基址固定（现代处理器常不区分）。
    \item \textbf{相对寻址忘记左移}：MIPS 分支偏移以“字”为单位，$EA = PC + (\text{offset} \ll 2)$，不是简单的 $PC + \text{offset}$。
    \item \textbf{忘记恢复 \$ra}：若过程内还会调用其它过程，必须先保存 \$ra 再调用，否则返回地址被覆盖，\texttt{jr \$ra} 将跳错。
    \item \textbf{栈指针方向弄反}：MIPS 栈向低地址生长，分配栈帧用 \texttt{addi \$sp, \$sp, -n}，释放用 \texttt{+n}。
    \item \textbf{误解寄存器号位宽}：32 个寄存器只需 5 位（$2^5=32$），因此 rs/rt/rd 各占 5 位，而不是把 32 位都留给一个操作数。
\end{itemize}
